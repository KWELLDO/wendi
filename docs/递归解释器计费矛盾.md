# 全景：递归解释器的产品与商业设计

## 1. 核心矛盾（宪法性问题）

```text
产品理念：鼓励问到底 → 越深越有价值
计费理念：按深度收费 → 越深越贵
结果：用户自我审查 → 不问到底 → 产品自我否定
```

这不是计费 bug，是**产品在教用户少问**。计费结构是最硬的交互设计。

**异化层面**：提问从“世界如何”变成“我买得起多少答案”。认知过程被交换价值中介，人的本质力量无法充分外化。

---

## 2. 产品设计

### 2.1 核心机制

递归解释器不是“无限问答”，而是**有结构的追问 + 收敛引导**。

三个动作：

1. **拆解**：把模糊困惑拆成可追问的子问题
2. **重构**：换角度、给反例、暴露隐含假设
3. **结晶**：把探索收敛为可复述、可验证、可行动的产物

### 2.2 用户旅程

```text
模糊困惑 → 递归追问 → 收敛检测 → 结晶交付 → 复用/分享/迭代
   ↑                                      ↓
   └──────── 贡献路径换额度 ←─────────────┘
```

### 2.3 深度判断：不按次数，按结构

“划词 50 次”是不是深度？看结构：

| 信号 | 浅层重复 | 深度探索 |
| --- | --- | --- |
| 问题演化 | 同一层级换词 | 从“是什么”到“为什么”到“如果…会怎样” |
| 自我修正 | 无 | “等等，我之前的假设错了” |
| 可复述性 | 无法总结 | 能用自己的话讲清链条 |
| 指向行动 | 无 | “那我该怎么做” |
| 元认知 | 无 | “我为什么一直在这个问题上打转” |

**产品职责**：识别收敛 vs 打转，主动引导，而不是按次数收费。

### 2.4 认知摩擦（替代计费闸门）

免费探索不按次数收费，但引入**认知摩擦**：

- 每 N 轮要求用户用自己的话总结一次
- 检测到原地打转时，主动建议换角度/给反例/明确目标
- 提供“继续深挖” vs “结晶输出”的选择

这不是收费，是**引导反思**。摩擦本身是产品价值，不是惩罚。

### 2.5 交付形态（具体）

| 形态 | 说明 | 适用 |
| --- | --- | --- |
| 解释文档 | 结构化、可复述、带引用 | 个人 |
| 思维图谱 | 节点+关系+演化路径 | 个人/团队 |
| 决策方案 | 选项+推理链+反例+行动项 | 决策者 |
| 可验证报告 | 引用+置信度+推理链 | 研究者 |
| API/JSON | 程序化访问 | 开发者 |
| 协作空间 | 多人追问+评审+共享 | 团队 |
| 课程包 | 学习路径+材料 | 教育 |

**关键**：交付是**过程的结晶**，不是过程的计费单位。

## 3. 商业设计

### 3.1 计费原则

**探索去价格化，收敛引导化，交付价值化。**

- 不让边际价格直接截断追问
- 用户不该因为穷而变保守
- 商业价值在“把理解变成可行动、可验证、可规模化”的环节捕获

### 3.2 收入来源

| 层级 | 内容 | 计费方式 |
| --- | --- | --- |
| 免费层 | 无限递归，小模型，缓存，降速不阻断 | 免费 |
| 订阅层 | 无限递归，高级模型，存储，导出 | 月费/年费 |
| 增值层 | 可验证引用、私人知识库、协作、API、专家人工 | 按项目/席位/调用 |
| 机构层 | 学校、图书馆、企业、基金会采购 | 年度合同 |
| 贡献层 | 匿名贡献追问路径换额度 | 以贡献换 |
| 开发者层 | API、嵌入组件、白标 | 按调用量 |

### 3.3 防滥用：不靠收费，靠结构

| 滥用 | 应对 |
| --- | --- |
| 划词 50 次 | 收敛检测，主动引导 |
| 机械刷量 | 认知摩擦，要求总结 |
| 白嫖 | 贡献换额度，路径反哺系统 |
| 低质量递归 | 系统主动降速/建议换角度，不阻断 |

### 3.4 成本控制

- 缓存、模型路由、RAG、蒸馏、批处理
- 让深层追问的边际成本趋近于零
- 用户贡献的追问路径形成公共知识图谱，降低后续成本

### 3.5 成功指标

| 旧指标 | 新指标 |
| --- | --- |
| 追问次数 | 收敛率 |
| 深度收费 | 交付转化率 |
| 单次收入 | 留存/续费 |
| 使用时长 | 可复述性/行动率 |

## 4. 产品与商业对齐

```text
产品理念：问到底 → 解放认知
商业理念：探索免费，交付收费
对齐点：不让价格截断追问，让价值在结晶处捕获
```

**异化问题的解**：

人的本质力量外化，不是通过“问了多少次”计量，而是通过**是否形成了属于他自己的清晰理解与可行动方案**体现。计费不挡在过程中间，落在过程之后、产物之上。

---

## 5. 一句话全景

**递归解释器 = 有结构的追问 + 收敛引导 + 结晶交付。探索去价格化，交付价值化。计费不挡在追问中间，落在理解之后。**

如果你要画一张图：

```text
┌─────────────────────────────────────────────────┐
│                   用户旅程                        │
│  困惑 → 递归追问 → 收敛检测 → 结晶 → 复用/分享    │
└─────────────────────────────────────────────────┘
         ↑                              ↓
    ┌─────────┐                  ┌──────────┐
    │ 产品机制 │                  │ 商业捕获  │
    │ 拆解     │                  │ 订阅      │
    │ 重构     │                  │ 增值      │
    │ 结晶     │                  │ 机构      │
    │ 收敛引导 │                  │ API       │
    └─────────┘                  └──────────┘
         ↑                              ↓
    ┌─────────────────────────────────────────┐
    │ 贡献换额度 ← 路径反哺 ← 公共知识图谱      │
    └─────────────────────────────────────────┘
```

这个框架下，产品鼓励的是**有结构的追问、有意识的收敛、有产出的交付**，而不是无限问。商业价值在交付处捕获，不在追问处征税。
