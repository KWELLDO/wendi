- 日期：2026-09-23
- 定位：从"有人用"到"有人付钱"的最小闭环（对应 `docs/project-and-business.md` 的 **L1 · 个人 Pro 订阅**）

## 0. 一页结论

**v1 商业版 = 三条腿：**

1. **计费单位重构（深度奖励制）** —— 现在"按次计费"惩罚深度探索，与产品灵魂冲突，必须先改
2. **支付闭环** —— 推荐路径：**爱发电（跳转支付 + Webhook 自动开通）**，6% 费率、无需营业执照
3. **合规底线** —— 用户协议 + 隐私政策 + 备案路线决策（CEO 级，需你拍板）

**明确不做（v1 边界）**：团队版、发票系统、复杂计费、海外线、自动续费（订阅靠用户重复购买）。

### 1.1 计费单位重构：深度奖励制（v1 核心设计）

**问题**：现在每次解释都扣 1 次。用户越想"问到底"（产品最鼓励的行为），越快撞墙——计费在惩罚灵魂。

**新规则**：

| 动作 | 计费 |
|---|---|
| 主对话提问（chat） | 1 |
| 解释 depth 1–2 | 1 |
| **解释 depth ≥ 3** | **0（免费）** |
| 卡内追问（followup） | 0（追问属于深度探索） |

**效果**：一次"问到底"（1 次提问 + 2 次浅解释 + 20 层深挖）= 3 次预算。用户在任何深度都敢继续。

**宣传语**（也是差异化）：**「问底不按深度收费」**——竞品都按 token，只有这里的"到底"是免费的。

**实现**：前端已知道每张卡的 depth（层级），在请求里带上 `depth`；后端 `consume_quota(depth)`：depth≥3 或 followup 时跳过扣减。

## 2. 支付闭环

### 2.1 通道对比（2026-09 现状调研）

| 方案 | 费率 | 门槛 | 自动化 | 结论 |
|---|---|---|---|---|
| **爱发电** | 6%（1% 通道 + 5% 平台） | 个人即可 | ✓ 官方 API + Webhook | **✓ v1 采用** |
| 个人收款码 | 0% | 个人 | ✗ 纯手动 | 备用（大额/特殊渠道） |
| 微信小程序虚拟支付（2026 新开放个人） | ~1% | 个人可开 | ✓ | 需要小程序形态，Web 站不适用，观察 |
| 个体户 + 微信/支付宝官方 | ~0.6% | 需办营业执照 | ✓ | v2 规模化后 |
| 海外 MoR（Lemon Squeezy 等） | 5%+ | 个人可 | ✓ | 海外线再做 |

### 2.2 v1 支付流程（爱发电 + 备注邮箱自动开通）

```
用户点「升级 Pro」
  → 跳转爱发电（¥15/月 或 ¥128/年 两个档位）
  → 下单时在备注填「问底账号邮箱」（页面上说清楚）
  → 爱发电 Webhook POST → know.kwelldo.cn/api/hook/afdian
  → 服务端：验签 → 按备注邮箱匹配用户 → 直接升级 Pro + 写 orders 表
  → 用户回到问底 → 刷新 → Pro 生效
```

- **兜底**：备注邮箱写错/缺失时，订单落 `orders` 表（状态 pending），管理员可查 → 手动补开通或补发兑换码。
- **对账**：`orders` 表记录渠道订单号，可与爱发电后台对账。
- **退款**：走爱发电流程；本地收到退款通知则回滚 Pro 时长。

### 2.3 Webhook 安全

- 爱发电 Webhook 有签名（`sign`），服务端必须验签（密钥放 `/etc/wendi.env`）
- Webhook 端点独立限流 + 幂等（同一订单号只处理一次）

## 4. 数据模型

```sql
CREATE TABLE orders (
  id TEXT PRIMARY KEY,           -- 内部订单号 WD-<ts>-<rand>
  user_id INTEGER,               -- 匹配到的用户（未匹配=NULL）
  email_hint TEXT,               -- 爱发电备注里的邮箱
  channel TEXT NOT NULL,         -- afdian / manual / code
  channel_order_id TEXT UNIQUE,  -- 渠道订单号（幂等键）
  amount_cents INTEGER,
  plan_days INTEGER,             -- 30 / 365
  status TEXT DEFAULT 'pending', -- pending/paid/delivered/refunded
  code TEXT,                     -- 兜底兑换码（可空）
  created_at TEXT, updated_at TEXT
);
```
