# graph2d 轮次时间线（主对话多轮不再只是一个点）

- 日期：2026-09-27
- 触发：用户「主对话有了多轮对话后，图谱中的主对话，依旧只是一个点」
- 范围：`web/graph2d.html`（视图与布局）+ `web/index.html`（一个新字段）

## 问题

图谱只画会话树的 `children`。主对话的轮次存在 conv 节点的 `messages[]` 里、不在 `children` 里，
所以无论聊多少轮，主对话在图上永远是一个「◇ 对话」点。
这与产品立场冲突：时间线是唯一不可逆物（append-only）——被折叠掉的正是它。

## 决策：轮次是第一等节点，铺成底部时间线

- 一轮 = 一条 user 消息 + 其后的 assistant 回答；各轮铺成**底部水平链**（左→右 = 发生先后）。
- 深度语义不变：y 仍是「解释层数」。于是底部是对话轴，解释是**从轴上长出来的枝干**（第 1 层卡片悬在它那一轮之上）。
- 卡片挂在它**诞生那一轮**上，不再挂在抽象的「对话」点上。
- 卡内追问（`followups`）暂不展开，仍是 `+N` 徽标——它是同一张卡的续问，不是新一轮。

已否决：折叠卡片／轮数徽标（点击展开）。它不解决"看不到时间线"，只是把折叠藏得更深。

## 数据契约

- `web/index.html`：父节点是 conv 的划词卡片写入 `exp.turn = <1 起的轮次>`。
  来源消息 id 取自划词范围所在的 `[data-quote-scope][data-msg]`（`bubbleInfo.msgId`）。
  划自己写的提问（user 消息没有 id）或取不到 → 落到当前最后一轮。
- 老数据（无 `turn`）：按 `createdAt` 落在哪一轮之后归属；无时间则归最后一轮。
- 退化态：零消息对话仍是旧的单点「对话」；只有对话、没有卡片时也照画（时间线本身有意义）。

## 布局

- 轮次吃掉一条不小于 `TURN_W = 104` 的车道；有卡片的轮次，车道宽 = 该轮解释子树的宽度，轮次居中于子树之上。
- 轮次之间连 `path.edge.chain`（accent 色，读作时间轴）；解释枝干样式不变。
- assistant 还在 streaming 的轮次画虚线菱形（`n-turn.ghost`）。
- 点击轮次 → 右侧显示该轮「你问 / AI 答」+ 从这轮长出几张卡。

## 验证（2026-09-27，本地 8931 真服务 + 合成数据 + 真实划词路径）

- 合成会话（3 轮、卡片分布在第 1/2/3 轮、含一张无 `turn` 老卡）：轮次 x 递增、卡片各自落在对应轮次、
  链边 2 条、`stat = 4 张解释卡 · 1 条追问 · 3 轮对话`。
- 真实划词：在**第 1 轮**的回答里划词（此时对话已到第 2 轮）→ 卡片 `turn = 1`（不是最后一轮）；
  划第 2 轮的回答 → `turn = 2`；划自己的提问（无 id）→ 落最后一轮。
- 老数据兜底（`messages` 无 `at`、卡片无 `createdAt`/`turn`）：不崩，全部落最后一轮。
- 空对话 / 零卡片两个退化态：单点「对话」/ 只画时间线，均正常。
- `python3 -m unittest discover -s tests`：117 绿（后端未动）。
- 未动：`graph3d-test.html`（实验室）只读 `children`，不受影响。

## 来源栏扩展（2026-09-28）

点击解释卡时，右侧详情在正文上方展示「来源」：
- 高亮用户划出的词/短语，并显示其原文语境；原文语境与「图谱位置（父卡/轮次）」是两类信息，不能互相替代。
- 显示模型对该词在当前语境中作用的简短说明。
- 有用户自填疑惑时原样展示，并让同一次解释请求推测一个可能卡点；没有疑惑时也允许基于划词和语境作低把握推测。推测必须显式标成「可能」，不得臆测用户经历、能力或心理；材料不足时可如实表示无法可靠判断。
- 元数据与解释正文由同一次模型调用产生，流式接口用专用前缀分离；不额外发起一次调用。
- 旧卡仍显示已保存的划词和语境；缺少新元数据时使用明确标注的弱推测/旧卡提示，不伪装成历史模型输出。
- 验证（2026-09-28）：`python3 -m unittest discover -s tests -v` 126 绿；Python 编译和两个前端 inline script 的 `node --check` 通过；隔离 Chrome profile 用合成会话核对了来源栏顺序、卡点显示及用户原文的 HTML 转义；本地 `dev-graph` 服务首页/图谱页均返回 HTTP 200。
- 边界：未发起真实 LLM 请求；元数据提示词与流式拆分已用单元/桩调用验证，但模型是否稳定给出合适的语境说明和卡点推测，仍待真实使用反馈。
