# 第一部分 · 这个项目是什么

## 1. 一句话

**问底是一个"递归解释器"：在阅读中划选任何不懂的词，就地得到结合语境的解释；解释里还有不懂的，继续划，一层层问到底。**

在线体验：https://know.kwelldo.cn （测试期限量）

## 2. 它解决什么问题

用 AI 学习新领域时，最大的障碍不是信息不够，而是**术语过载**——AI 默认你拿着它的术语表说话。传统补救是"追问"，但追问是线性的：

1. 你问"什么是叠加态"，AI 解释了；
2. 解释里又出现"波函数坍缩"；
3. 你追问"什么是坍缩"，回来时**原来那段话已经滚走了**；
4. 两三轮之后，你迷失在聊天记录里，语境断裂，只能重开对话。

问底把这件事从"对话流"改造成"**可回退的空间**"：每次划词生成一张**就地展开的解释卡**，原句不动；解释卡里的新术语还能继续划，形成一棵**你自己的困惑之树**。学习过程第一次有了空间结构——能进入、能返回、能总览。

## 3. 核心交互（四步）

| 步骤 | 操作 | 发生什么 |
|---|---|---|
| ① 提问 | 在主对话输入问题 | AI 回答成为"可划词的材料" |
| ② 划词 | 鼠标划选任何词/短语 | 就地弹出金色的「解释」气泡 |
| ③ 下钻 | 点击解释 → 生成解释卡 | 结合**该词所处的句子**解释，不是词典义 |
| ④ 递归/回退 | 卡内继续划词；`Esc` 或 `Alt+←` 返回上一层；`↑↓` 切换兄弟解释；`Alt+Enter` / `Alt+→` 进入 | 深度无限，路径可逆，一切可回退 |

辅助能力：三档解释深度（说人话 / 标准 / 严谨）、划词时附一句自己的疑惑（解释先答它）、卡内追问、解释重讲、LaTeX 公式排版（KaTeX 内置）、导出整棵树为 Markdown、30 秒引导教程、设置面板（反馈 / 账号与同步 / 数据 / 关于；站长项默认隐藏）、右下角常驻反馈入口。

**"分形房间"隐喻**：每一层都是一个同构的房间——左边正文，右上是本层解释列表，右下是下一层的缩小预览。进入/返回是摄像机移动，深浅不会把字挤小。这解决了递归界面最常见的"套娃越缩越小"问题。

## 4. 设计立场（这个产品的宪法）

这四条不是功能列表，是**拒绝做某些功能**的承诺，全部推导自理论文档 `docs/clarity-and-vagueness.md`（含糊与清晰的辩证关系）：

1. **不评判** —— 没有"这么简单都不懂"，没有熟练度红绿，没有"已掌握/待复习"。困惑是学习材料，不是待消灭的缺陷。
2. **解释是材料，不是答案** —— 系统不给"这就是全部"的终审结论，判断永远在读者手里。
3. **允许含糊** —— 一词多解就并列呈现，不强行收敛；近义词不自动合并；图谱不为概念强制命名聚类。
4. **数据主权** —— 记录默认留在用户自己的浏览器（`localStorage`）；服务端只转发请求、托管账户；云同步是用户主动的备份行为。

这四条也是商业化的护城河所在：交互可以被抄袭，但一套一贯的立场凝聚出的用户信任与品牌声音，抄不走。

## 5. 功能全景

**已实现（v0.2.x）**
- 划词递归解释 + 分形房间导航 + 键盘全操作
- 三档解释深度；卡内追问；重讲
- 主对话（问题意识入口）+ 示例问题 + 30 秒引导教程
- 导出 Markdown
- 账户系统（注册/登录/三档配额 20/40/300 次·天）、兑换码升 Pro
- 云同步（本地优先，主动备份/载入）
- SSE 流式输出（划词/追问/对话边生成边显示）
- 内核事件缝（`explain.done / explain.error`），为扩展子系统预留

**实验中（独立分支/测试页）**
- 图谱实验室 `web/graph3d-test.html`：3D 术语时空图（塔=主题、Y=深度、Z=场次），含调参面板
- 图谱页导出 `web/graph2d.html`：当前视图 → PNG（纸色落款带、不随夜版反色）+ 图谱结构 JSON（解释卡正文/语境/追问，不含对话原文；生成中的卡不入 JSON）
- 分享卡片（`feat/share-card` 分支）：解释树切片的只读渲染，PNG + JSON

**规划（见 memo.md 路线图）**
- 知识图谱正式版（术语卡积累成网）
- 多会话/多主题
- 笔记（卡片批注）
- 分享 permalink（只读链接）
- 团队版

## 6. 技术架构

```
web/index.html   全部前端（单文件、零构建）：分形房间 + 摄像机 + 键盘导航 + SSE 渲染
web/vendor/katex 内置 KaTeX：正文/解释/预览里的 LaTeX 排版
server.py        薄代理：LLM 转发（多 key 轮换）+ 限流 + 配额 + 账户 + 兑换码 + 云同步
kernel.py        内核：事件总线 + 服务注册 + 作用域生命周期（借鉴 cordis 语义，纯标准库）
prompts.py       提示词资产——这个项目真正的核心软件资产：解释器人格三件套
db.py / auth.py  SQLite 数据层 + PBKDF2 认证
deploy/          systemd + nginx 幂等部署件
tests/           内核测试
```

三个刻意坚持的工程约束：

1. **零第三方依赖（后端只用 Python 标准库）**——部署成本趋近于零，一台任意 VPS 即可运行；安全面极小。
2. **前端单文件零构建**——没有 node_modules，没有构建链；产品迭代周期以小时计。
3. **提示词即核心资产**——`prompts.py` 里沉淀的是"解释器人格"（不评判、语境化、允许并列），模型可换（任何 OpenAI 兼容端点），人格可迁移。

代码规模约 2500 行（后端 ~800，前端 ~900，测试与部署件其余）。单人可维护。

**模型无关**：默认 DeepSeek（便宜），任何 OpenAI 兼容端点可替换；BYOK（自带 key）模式让高级用户完全绕开你的成本。

## 7. 部署形态

- 官方实例：`know.kwelldo.cn`（腾讯云单机 + systemd + nginx 反代 + 免费证书）
- 自部署：clone → 设一个 API key → `python3 server.py`，五分钟内跑通；AGPL-3.0 保证自部署权利
- 数据：SQLite 单文件 + 用户浏览器 localStorage；无大数据基础设施

# 第二部分 · 商业化方案

## 0. 先说诚实的结论

问底当前是一个**优秀的功能、有品味的产品原型，但还不是一门生意**。缺三样东西：留存机制、增长渠道、变现轨道。好消息是运营成本趋近于零（一台百元级 VPS + DeepSeek API 按量，月成本 < ¥100），**这个项目输不了**；但"不输"不等于"赢"。以下方案的总体策略是：**A 作品为底座、B 工具生意做探索、C B2B 楔子挂墙观察**——以 W4 留存 > 25% 作为是否加码的分界线。

## 1. 市场与用户定位

**痛点真实且普适**：AI 生成内容越普及，术语过载越严重。三类画像清晰的早期用户：

| 画像 | 场景 | 付费意愿 |
|---|---|---|
| 跨领域自学者 | 程序员学 ML、产品学金融、研究者闯入邻近学科 | 中——为效率付小额订阅 |
| 学生/考研考公群体 | 教材与讲义术语密集 | 低但量大——价格敏感 |
| 专业阅读者 | 论文、白皮书、行业报告 | 较高——时间是真金白银 |

**竞争现实（不粉饰）**：大厂（Kimi/豆包/ChatGPT）可以在两周内抄走"划词递归解释"的交互，且免费有渠道。可防御的资产只有三个：①用户积累下来的个人术语网（数据资产）；②"不评判/允许含糊"的立场品牌（信任资产）；③独立开发者的迭代速度与品味。商业化所有动作都应围绕加固这三项，而不是围绕功能罗列。

## 2. 四条收入线（按启动顺序）

### L1 · 个人 Pro 订阅（免费增值，最先做）

- 免费：40 次/天（现行）
- **Pro：¥15/月 或 ¥128/年**——300 次/天 + 云同步 + 全量导出 + 优先队列
- 关键设计原则：**卖"量"与"便利"，绝不卖"深度"**。现行按次计费会惩罚"问得深"的用户，与产品灵魂冲突——改造配额为"深度奖励"制（问到底不受罚）是 L1 上线的前置工作。
- 支付轨道：微信/支付宝（或爱发电、面包多等中间件），兑换码体系已就绪，缺的只是支付闭环。

### L2 · 团队版（B2B 小单，第二个季度试）

- **¥30/人/月**，5 人起
- 卖点不是额度，是**共享术语库**：新人入职把公司黑话一层层问下来，术语网沉淀为团队资产；研究组同理
- 候选场景：远程团队 onboarding、高校课题组、读书会
- 需要先完成：多会话、数据地基（cards 表 + 权限），即路线图前两步

### L3 · 嵌入组件（The Widget，差异化最强的一条线）

把"划词递归解释"做成**任何文档站/长文平台可嵌入的组件**（脚本一行接入）：

- 技术文档站、论文平台、在线教育内容是术语过载重灾区
- 计费：按解释调用量或站点年费
- 这条线把问底从"一个网站"变成"一种能力"，且天然对冲大厂抄交互的风险（他们抄产品，不会做嵌入生意）
- 前置：kernel 事件缝已就绪，需要一个可分发的 SDK 包装 + 配额网关

### L4 · 分享卡片与 permalink（获客飞轮，变现在后）

- 分享卡片（已开发）：每次深度学习产出一张可传播的图——**获客渠道，不直接收钱**
- permalink（只读链接）：卡片表落库后的自然产物；免费，带访问统计
- 立场约束：permalink 免费，卖的是后面 L1 的容量

## 3. 增长引擎（三个飞轮）

1. **分享飞轮**：导出的 PNG/链接自带水印与入口 → 每一次"问到底"都是一次传播。分享卡片是点火器。
2. **内容飞轮**：`docs/clarity-and-vagueness.md` 是真正有分量的思想内容（清晰与含糊的辩证、知识政体、星丛）。改写成系列文章（知乎/公众号/少数派）——"术语过载"是全民痛点，立场文章比广告便宜一个数量级。
3. **开源飞轮**：BYOK 自部署 + AGPL 在 V2EX/Show HN/即刻发布——攒贡献者、攒声誉、攒 L3 的潜在客户。

## 4. 成本结构（为什么这个盘子输不了）

| 项 | 月成本 |
|---|---|
| VPS（单机） | ¥50–100 |
| DeepSeek API（1000 次解释 ≈ ¥2–4） | 视量，早期 < ¥50 |
| 域名/杂项 | < ¥20 |
| **合计** | **< ¥200/月** |

单人 + 零依赖 + 免费模型价格战红利 = 可以用年为单位等待留存证据，没有烧钱压力。这是小产品最大的战略优势：**不被迫在证据到来之前商业化**。

## 5. 合规与风险清单

| 风险 | 等级 | 应对 |
|---|---|---|
| 生成式 AI 服务备案（.cn 域名 + 面向公众） | **高，CEO 级** | 三选一：完成备案 / 调整为 BYOK 自部署为主 / 转向海外用户。需专业意见，这是"敢不敢把按钮做大"的前提 |
| 大厂复制交互 | 中 | 加固三项资产（术语网/立场/速度），做 L3 嵌入能力 |
| UGC 社区合规（若做社区广场） | 高 | 押后；先做只读分享，不做公开内容池 |
| 单人巴士系数 | 中 | 文档已厚（memo/README/理论文档），AGPL 保证项目不随人亡 |
| 支付与退款纠纷 | 低 | 订阅制小额，标准条款 |

## 6. 分阶段路线（把工程顺序和商业顺序钉在一起）

**第 0 阶段 · 保命（1–2 周）**
合规评估定调 · 清理代码中个人基础设施痕迹 · 移动端划词

**第 1 阶段 · 留存地基（3–6 周）**
数据地基：cards(UUID + visibility) + explain_events 事件流 → `store` 服务（user_id 强制作用域）→ 多会话 → 知识图谱 v1（2D 先行）→ 分享卡片（分支已就绪）→ 匿名指标埋点（北极星：每周到底次数）

**第 2 阶段 · 变现轨道（7–12 周）**
支付闭环 → L1 Pro 上线（配额改深度奖励制）→ 分享 permalink → 浏览器插件或文档站组件二选一 → 20 个种子用户深访

**第 3 阶段 · 加码或收割（第 2 季度起）**
- W4 留存 > 25% 且有自然分享 → 加码 L1/L2，启动团队版试点
- 留存不及格 → 回到产品：A 作品路线养着，L3 嵌入组件作为 B2B 试探

## 7. 判断这门生意的三个里程碑

1. **有人第二次回来**（D7 > 15%）——证明交互价值
2. **有人问"能不能分享给同学/同事"**（分享卡片上线后自然出现）——证明传播价值
3. **有人愿意为容量付 ¥15**（L1 上线首月转化 > 2%）——证明生意存在

三个都发生之前，所有成本控制在小数点后；第一个发生之后，才值得谈融资或全职。

## 结语

问底的独特之处在于：它对"学习"有一个立场（含糊与清晰的辩证），并且把立场做进了每一次交互（不评判、可回退、允许含糊）。商业化不要求出卖这个立场——恰恰相反，**这个立场是它唯一抄不走的东西**。所有收入线的设计原则就一句：

> 卖容量、卖便利、卖团队协作；永远不卖评判，永远不把用户的困惑变成焦虑。

（工程问题清单与优先级见 `memo.md`；理论根基见 `docs/clarity-and-vagueness.md`。）
